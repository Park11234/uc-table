# 구조

## 한눈에

```
브라우저 ──▶ index.html (단일 파일)
               ├─ 상태 S  … localStorage("uc-table.v1")에만 저장, 서버 없음
               ├─ 음식 DB … FOODS 1,750종(영양식 39종·시판 과자·사탕·젤리 83종·라면 55종·마트 시판 식품 17종·v1.9.0 시판 제품 1,059종 포함) + 식약처·국가표준식품성분표·제품 표시 영양값(MFDS·MICRO) + 별명/아이콘/분량 표
               ├─ 판정    … foodStatus(음식, 사용자 맥락) → ok / caution / later / avoid + 이유
               ├─ 식단    … samplePlan() → 끼니 메뉴 1,174개 중 조건을 통과한 것으로 7일, 양 조절
               ├─ 궁금한 점 … QA 45문항(근거 원문 인용) → 음식 검색·음식 정보와 연결
               └─ 화면    … render() → renderInner() → viewOnboard(첫 실행) · viewPlan·viewLog·viewFood·viewMe(탭 4개)
                             + 하위 화면 SCR(nutri 영양·report 보고서·asks 물어볼 것·set-* 설정·meal 끼니 …)
```

- 프레임워크·번들러가 없습니다. 앱 코드는 `src/app/app.src.html` 한 파일(약 3,900줄)에 CSS와 JS가 모두 들어 있고,
  빌드는 생성 데이터를 표시자 자리에 넣기만 합니다. 오프라인 빌드의 외부 요청은 0건입니다.
- 서버가 없으므로 기록은 기기 밖으로 나가지 않습니다. 내보내기는 사용자가 누를 때만 파일로 저장됩니다.

## 상태

`S` 하나가 전체 상태입니다. 저장은 `save()`, 불러오기는 `normalizeState()`가 맡습니다.
저장이 실패하거나(사생활 모드, 용량 초과) 저장된 값을 읽지 못하면 원본을 지우지 않고 경고와 백업 복사 버튼을 먼저 띄웁니다.

기록 보호(v1.8.0):

- **여러 창**: 저장할 때마다 `localStorage`의 `uc-table.v1.rev` 숫자를 하나 올립니다. 다른 창이 저장하면 `storage` 이벤트(또는 저장 직전 비교)로 이 창의 숫자가 뒤처진 것을 알고 `STALE`로 바꿔 저장을 멈추고, '다시 불러오기'(`reloadState`)를 안내합니다. 바뀐 내용이 없으면 저장하지 않습니다(`LAST_JS` 비교).
- **백업 뒤 바뀐 날**: 기록이 바뀐 날짜를 `chgDays`에 모으고, 백업 파일 저장·복사 때 비웁니다. 홈과 '데이터·백업'에 '백업 뒤 n일치'로 보입니다.
- **불러오기**: `restoreFromText`가 지금 기록과 백업의 기록 수·기간을 표로 보여 주고, '합치기'(`mergeStates`: 지금 기록이 이기고, 백업에만 있는 날짜·항목을 더함) 또는 '백업으로 바꾸기'를 고릅니다. 바꾸기 직전 기록은 `uc-table.v1.prev`에 보관해 '되돌리기'(`restoreUndo`)가 가능합니다.
- **저장 공간 보존**: 첫 실행 설정을 마친 뒤 `navigator.storage.persist()`를 한 번 요청하고 결과(`S.persist`)를 '데이터·백업'에 보여 줍니다.
- **예기치 못한 오류**: `error`·`unhandledrejection`을 받아 위쪽 `#errbar`에 '백업 내용 복사·새로고침'을 띄웁니다(같은 오류는 한 번만).

`normalizeState()`는 백업 복원에도 쓰이며, 다음을 보장합니다.

- 날짜는 실제 달력 날짜만(`2026-99-99` 같은 값은 버림), 화면에 보이는 글자 항목은 글자만(객체·배열 차단)
- 증상 숫자는 화면에서 고를 수 있는 범위로(예: 급박감 0~3, 배변 0~40), 수분은 0~60잔, 영양값은 0 이상의 숫자
- 형식이 맞는 기록은 한 값도 바꾸지 않음(멱등) — `tests/checks/load_state.cjs`로 확인
- 이 함수는 앱을 여는 순간 실행되므로, 뒤에서 정의되는 값(`today`, `md`, `EXTRA` 등)을 쓰지 않음
  (쓰면 초기화 전 참조 오류로 **정상 기록을 손상으로 오인**하게 됨)

## 단계 판정

증상 기록에서 SCCAI 점수를 계산해 세 단계 중 하나를 고릅니다.
사용자가 직접 단계를 고정할 수도 있습니다(`stageMode`).

| 단계 | 이름 | 기준 |
|---|---|---|
| 1 | 저잔사식 | 활동기. 섬유·질긴 질감·자극을 줄이고 부드럽게 익힌 음식 |
| 2 | 이행식 | 증상이 가라앉는 중. 익힌 채소와 단백질을 조금씩 넓힘 |
| 3 | 지중해식 | 관해기. 채소·과일·통곡물·생선 중심, 가공식품·붉은 고기 제한 |

## 음식 판정

`foodStatus(음식, 맥락)`은 다음을 차례로 확인해 가장 강한 판정과 그 이유만 돌려줍니다.

1. 개인 조건 — 알레르기 태그, 유당, 의료진 지시, 싫어하는 음식, 개인 주의 음식
2. 항상 피하는 음식(`ms = 9`) — 술, 초가공식품, 튀김, 신장질환자용·경관급식 전용 영양식 등
3. 단계 조건 — 음식의 시작 단계(`ms`)가 현재 단계보다 높으면 '지금은 보류'
4. 속성 조건 — 섬유량(한 끼 2 g 기준), 채소 35 g 상한, 짠 음식·기름진 음식, 매운 양념,
   가스를 늘리는 재료(FODMAP), 질긴 질감, 1회 분량 나트륨, 특수의료용도식품·질환용 영양식
5. 자료 없음 — 저잔사식 단계에서 식이섬유 값이 없는 식물성 음식은 양 기준을 확인할 수 없어 '주의해서'

영양값이 없는 항목은 0으로 치지 않습니다. `hasNut(음식, 영양소)`로 확인하고, 합계(`totals`)는 자료가 있는 값만 더한 뒤
빠진 음식 이름을 따로 모아(`miss`) 화면에 "○○ 자료가 없는 △△는 합계에서 빠졌어요"로 알립니다.

외식 메뉴 판정(`ruleCheck`)은 먼저 개인 조건을 검사하고,
메뉴 이름이 목록의 음식과 정확히 일치하면 그 음식의 판정을 그대로 씁니다.
일치하지 않을 때만 재료 이름에서 키워드를 찾아 판단합니다(곤약면·당면처럼 '면'이 붙어도 밀이 아닌 것은 제외 목록으로 거름).

## 예시 식단(오프라인)

`samplePlan()`은 7일 식단을 만듭니다(v1.7.0부터 앱의 유일한 식단 방식).

1. 메뉴 1,174개(생성 1,144 + 직접 쓴 30 + 내가 만든 메뉴) 중 모든 식품이 그날 판정을 통과한 것만 씀(저잔사식은 채소 반찬 한 끼 1가지)
2. 날짜마다 목록의 다른 위치에서 시작해, 한 주에 같은 메뉴·같은 점심·저녁 주재료를 먼저 건너뜀
3. 끼니 평가가 '좋음'인 식품이 든 메뉴를 먼저, '나쁨'인 식품은 뺌. 관해기에는 지중해식 메뉴를 먼저
4. 아침 단백질은 하루 목표의 20%(적어도 12 g) 이상, 나트륨은 끼니와 하루 누적으로 상한 안
5. 체중과 BMI로 정한 열량(저체중 35·정상 30·비만전단계 이상 25 kcal/kg, 대한비만학회)·단백질(ESPEN) 목표에 맞춰 밥·죽·면(0.8~1.5배)과 단백질 반찬(최대 1.5배) 양을 조절
6. 끼니마다 곁들임을 하나 붙이는데, 그 끼니까지 쌓인 칼슘이 하루 권장섭취량의 1/3·2/3·전부에 못 미치면 칼슘 100 mg 이상인 곁들임(우유·요거트 등)을 먼저 고름(관해기 저녁에는 지중해식 곁들임 먼저)
7. 관해기에는 양을 조절한 뒤 하루 식이섬유가 충분섭취량에 못 미치면 곁들임을 섬유가 더 많은 것으로 바꿈(나트륨 상한 안, 칼슘은 줄이지 않음)

교체한 메뉴는 메뉴 키로 저장하고(`setSwap`), 메뉴 고르기 화면에서 직접 고르거나 내가 만든 메뉴로 바꿀 수 있습니다.

## 내 정보 편집과 저장(v1.7.1)

기본 정보·알레르기·복용 약·식성·의료진 지시 화면은 열 때 `S.profile`·`S.orders`를 복사한 초안(`PE`)을 만들고, 화면의 입력과 버튼은 초안만 바꿉니다(`PP()`·`PO()`). '저장'(`peSave`)을 눌러야 초안을 기록에 넣고 기기에 저장합니다. 뒤로 가기·취소에서 초안이 처음과 다르면(`peDirty`) 저장할지 묻고, 버리면(`peDiscard`) 입력칸 값을 다시 읽지 않고 닫습니다(`peLeave`). 편집 화면을 벗어나면 그리기 전에 초안을 버립니다.

## 영양 화면·목표(v1.8.0)

- `targets()`는 BMI(`bmiInfo`)로 체중 1 kg당 열량을 고르고, 사용자가 정한 목표(`S.goals`)가 있으면 그 값으로 바꾼 뒤 바꾼 항목을 `custom`에 적습니다.
- 먹은 양 합계(`eatenTotals`)는 '먹음'을 누른 끼니(비율 반영)와 직접 추가한 음식을 더합니다. 막대(`dbarHTML`)는 계획한 양과 먹은 양을 한 줄에 그리고, `shortOK(날짜)`(지난 날이거나 오늘 19시 이후)일 때만 모자람을 경고색으로 칠합니다.
- 체중 감소(`weightLoss`·`glimHTML`)는 GLIM 기준으로 6개월 안·6개월 넘는 기간의 감소율을 계산해 1·2단계 안내를 띄웁니다.
- FODMAP 1회량(`FSERV`, 빌드 때 `fodmap_serv.py`에서 넣음)과 요리 값 종류(`DISHX`)는 음식 정보·먹은 음식 추가·끼니 화면에서 씁니다.

## 궁금한 점(v1.7.0)

`QA`(빌드 때 `qa.py`에서 넣음)는 질문·핵심어·답·근거(자료 이름, 위치, 원문 문장, 참고문헌 번호)·관련 음식을 담습니다.

- 검색(`qaMatch`): 검색어가 핵심어와 같으면 3, 핵심어에 들어 있거나 두 글자 이상 핵심어가 검색어에 들어 있으면 2, 질문에 있으면 1, 답에만 있으면 0.5. 한 글자 핵심어(물·술·회·굴)는 같을 때만 맞춰 '물김치'가 수분 질문에 걸리지 않게 함
- 음식 검색은 점수 1 이상인 질문을 3개까지 결과 위에 보여 주고, 음식 정보는 그 음식을 `foods`에 둔 질문을 보여 줌
- 질문 화면(`scrQA`)은 종류 칩과 검색, 펼친 답 안의 관련 음식 칩(지금 판정), 근거 원문 펼치기로 구성. 결과 목록은 음식 검색처럼 같은 내용이면 다시 그리지 않음(`setListHTML`)
- 인용문 대조는 앱이 아니라 단위 점검이 함([근거 목록](evidence.md#궁금한-점의-근거-원문-대조v170))

## 배포본

| 산출물 | 만드는 법 | 쓰임 |
|---|---|---|
| `src/app/index.html` | `build_app.py` | 원본. 글꼴·PDF 라이브러리를 CDN에서 불러옴 |
| `public/` | `python3 tools/build_offline.py` | GitHub Pages로 올리는 PWA(오프라인 설치용) |
| `dist/uc-table-offline.html` | 같은 스크립트 | 파일 하나로 여는 오프라인 앱(약 3.6 MB) |

오프라인 빌드는 html2canvas·jsPDF를 파일 안에 인라인하고 구글 폰트 링크를 지웁니다.
글꼴은 기기 글꼴로 대체되며, 나머지 기능은 모두 같습니다(앱이 AI나 외부 서버를 부르지 않음).

### 서비스 워커(설치형 앱) 갱신

- 캐시 이름 = `uc-table-` + `public/index.html` 내용의 SHA-256 앞 10자리. 앱이 바뀌면 `sw.js`가 바뀌고, 브라우저가 새 워커를 설치합니다.
- 설치할 때 `cache:"reload"`로 받아 HTTP 캐시에 남은 옛 파일이 새 캐시에 섞이지 않게 합니다.
- 새 워커가 켜지면 옛 캐시(`uc-table-*`)를 지우고, 이후 여는 화면부터 새 버전이 나옵니다.
- 요청은 캐시 우선(오프라인에서도 즉시 열림), 캐시에 없으면 네트워크에서 받아 저장합니다.

### 알림

서버가 없어 앱이 스스로 알림을 보낼 수 없습니다. 대신 식사·증상 기록 시간을 매일 반복하는 캘린더 파일(.ics)로 만들어
휴대폰 캘린더 앱이 알리게 하고, 앱을 열었을 때 그 시간이 지났는데 기록이 없으면 홈에 안내를 띄웁니다.
