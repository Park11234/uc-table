# 구조

## 한눈에

```
브라우저 ──▶ index.html (단일 파일)
               ├─ 상태 S  … localStorage("uc-table.v1")에만 저장, 서버 없음
               ├─ 음식 DB … FOODS 439종 + 식약처 영양값(MFDS) + 별명/아이콘/분량 표
               ├─ 판정    … foodStatus(음식, 사용자 맥락) → ok / caution / later / avoid + 이유
               └─ 화면    … render() → renderInner() → viewPlan·viewLog·viewFood·viewNutri·viewMe
```

- 프레임워크·번들러·빌드 산출물이 없습니다. HTML 한 파일(약 3,500줄)에 CSS와 JS가 들어 있고,
  외부 요청은 오프라인 빌드에서 0건입니다.
- 서버가 없으므로 기록은 기기 밖으로 나가지 않습니다. 내보내기는 사용자가 누를 때만 파일로 저장됩니다.

## 상태

`S` 하나가 전체 상태입니다. 저장은 `save()`, 불러오기는 `normalizeState()`가 맡아
없는 키를 채우고 형식이 깨진 값을 버립니다. 저장이 실패하거나(사생활 모드, 용량 초과)
저장된 값을 읽지 못하면 원본을 지우지 않고 경고와 백업 복사 버튼을 먼저 띄웁니다.

| 키 | 내용 |
|---|---|
| `profile` | 키·몸무게·나이·성별·알레르기·유당·복용약·싫어하는 음식·예산 |
| `logs[날짜]` | 배변·혈변·급박감·통증·컨디션 등 증상 기록(SCCAI 계산의 입력) |
| `orders` | 의료진 지시(저잔사식·수분 제한 등) |
| `triggers` | 개인 주의 음식 |
| `extras`, `water`, `weights` | 먹은 음식·수분·몸무게 |
| `consent` | 이용 고지 동의와 AI 사용 동의 |

## 단계 판정

증상 기록에서 SCCAI 점수를 계산해 세 단계 중 하나를 고릅니다.
사용자가 직접 단계를 고정할 수도 있습니다(`stageMode`).

| 단계 | 이름 | 기준 |
|---|---|---|
| 1 | 저잔사식 | 활동기. 섬유·질긴 질감·자극을 줄이고 부드럽게 익힌 음식 |
| 2 | 이행식 | 증상이 가라앉는 중. 익힌 채소와 단백질을 조금씩 넓힘 |
| 3 | 지중해식 | 관해기. 채소·과일·통곡물·생선 중심, 가공식품·붉은 고기 제한 |

## 음식 판정

`foodStatus(음식, 맥락)`은 다음을 차례로 확인해 가장 강한 판정과 그 이유만 돌려줍니다.

1. 개인 조건 — 알레르기 태그, 유당, 의료진 지시, 싫어하는 음식, 개인 주의 음식
2. 항상 피하는 음식(`ms = 9`) — 술, 초가공식품, 튀김 등
3. 단계 조건 — 음식의 시작 단계(`ms`)가 현재 단계보다 높으면 '지금은 보류'
4. 속성 조건 — 섬유량(한 끼 2 g 기준), 채소 35 g 상한, 짠 음식·기름진 음식, 매운 양념,
   가스를 늘리는 재료(FODMAP), 질긴 질감

외식 메뉴 판정(`ruleCheck`)은 먼저 개인 조건을 검사하고,
메뉴 이름이 목록의 음식과 정확히 일치하면 그 음식의 판정을 그대로 씁니다.
일치하지 않을 때만 재료 이름에서 키워드를 찾아 판단합니다.

## 음식 데이터 파이프라인

음식 데이터는 손으로 적지 않고 스크립트로 만들어 앱에 주입합니다.

```
src/data/spec1~6.py      음식 정의(이름·분류·단계·태그·분량·별명·조리법)
src/data/templates.py    판정 설명 문장 템플릿(근거 번호 포함)
        │
        ├─ generate_dataset.py  식약처 CSV에서 행을 찾아 영양값을 붙임 → generated/gen_out.json
        │
        └─ build_app.py
             ├─ apply_1_dataset.py   app.base.html에 음식 데이터 주입
             ├─ apply_2_rules.py     판정·검색·화면 규칙 패치
             └─ apply_3_existing.py  기존 음식의 단계·태그·설명 교정
                                      → src/app/index.html
```

`python3 src/data/build_app.py`는 `src/app/app.base.html`에서 시작해
현재 배포본과 **바이트 단위로 같은** `src/app/index.html`을 다시 만듭니다.

## 배포본

| 산출물 | 만드는 법 | 쓰임 |
|---|---|---|
| `src/app/index.html` | 파이프라인 | 원본. 글꼴·PDF 라이브러리를 CDN에서 불러옴 |
| `public/` | `python3 tools/build_offline.py` | GitHub Pages로 올리는 PWA(오프라인 설치용) |
| `dist/uc-table-offline.html` | 같은 스크립트 | 파일 하나로 여는 오프라인 앱(약 1.1 MB) |

오프라인 빌드는 html2canvas·jsPDF를 파일 안에 인라인하고 구글 폰트 링크를 지웁니다.
글꼴은 기기 글꼴로 대체되며, AI 기능은 자동으로 꺼지고 나머지 기능은 그대로 동작합니다.
