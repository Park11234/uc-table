# 구조

## 한눈에

```
브라우저 ──▶ index.html (단일 파일)
               ├─ 상태 S  … localStorage("uc-table.v1")에만 저장, 서버 없음(자동 보관본 7일·암호화 열쇠는 IndexedDB)
               ├─ 음식 DB … FOODS <!--n:foods-->1,771<!--/n-->종(일반 <!--n:general-->538<!--/n-->종 + 시판 제품 <!--n:prod-->1,233<!--/n-->종, 시판 표시는 데이터의 PROD 목록) + 식약처·국가표준식품성분표·제품 표시 영양값(MFDS·MICRO) + 별명/아이콘/분량 표
               ├─ 판정    … foodStatus(음식, 사용자 맥락) → ok / caution / later / avoid / ban + 이유
               ├─ 식단    … samplePlan() → 끼니 메뉴 <!--n:menus-->1,174<!--/n-->개 중 조건을 통과한 것으로 7일, 양 조절
               ├─ 궁금한 점 … QA <!--n:qa-->51<!--/n-->문항(근거 원문 인용 <!--n:qaev-->169<!--/n-->건) → 음식 검색·음식 정보와 연결
               └─ 화면    … render() → renderInner() → viewOnboard(첫 실행) · viewPlan·viewLog·viewFood·viewMe(탭 4개)
                             + 하위 화면 SCR(nutri 영양·report 보고서·asks 물어볼 것·set-* 설정·meal 끼니 …)
```

- 프레임워크·번들러가 없습니다. 앱 코드는 `src/app/app.src.html` 한 파일(약 5,100줄)에 CSS와 JS가 모두 들어 있고,
  빌드는 생성 데이터를 표시자 자리에 넣기만 합니다. 오프라인 빌드의 외부 요청은 0건입니다.
- 서버가 없으므로 기록은 기기 밖으로 나가지 않습니다. 내보내기는 사용자가 누를 때만 파일로 저장됩니다.

## 상태

`S` 하나가 전체 상태입니다. 저장은 `save()`, 불러오기는 `normalizeState()`가 맡습니다.
저장이 실패하거나(사생활 모드, 용량 초과) 저장된 값을 읽지 못하면 원본을 지우지 않고 경고와 백업 복사 버튼을 먼저 띄웁니다.

기록 보호(v1.8.0):

- **여러 창**: 저장할 때마다 `localStorage`의 `uc-table.v1.rev` 숫자를 하나 올립니다. 다른 창이 저장하면 `storage` 이벤트(또는 저장 직전 비교)로 이 창의 숫자가 뒤처진 것을 알고 `STALE`로 바꿔 저장을 멈추고, '다시 불러오기'(`reloadState`)를 안내합니다. 바뀐 내용이 없으면 저장하지 않습니다(`LAST_JS` 비교).
- **백업 뒤 바뀐 날**: 기록이 바뀐 날짜를 `chgDays`에 모으고, 백업 파일 저장·복사 때 비웁니다. 홈과 '데이터·백업'에 '백업 뒤 n일치'로 보입니다.
- **불러오기**: `restoreFromText`가 지금 기록과 백업의 기록 수·기간을 표로 보여 주고, '합치기'(`mergeStates`: 지금 기록이 이기고, 백업에만 있는 날짜·항목을 더함) 또는 '백업으로 바꾸기'를 고릅니다. 바꾸기 직전 기록은 `uc-table.v1.prev`에 보관해 '되돌리기'(`restoreUndo`)가 가능합니다.
- **저장 공간 보존**: 첫 실행 설정을 마친 뒤 `navigator.storage.persist()`를 한 번 요청하고 결과(`S.persist`)를 '데이터·백업'에 보여 줍니다.
- **예기치 못한 오류**: `error`·`unhandledrejection`을 받아 위쪽 `#errbar`에 '백업 내용 복사·새로고침'을 띄웁니다(같은 오류는 한 번만).

`normalizeState()`는 백업 복원에도 쓰이며, 다음을 보장합니다.

- 날짜는 실제 달력 날짜만(`2026-99-99` 같은 값은 버림), 화면에 보이는 글자 항목은 글자만(객체·배열 차단)
- 증상 숫자는 화면에서 고를 수 있는 범위로(예: 급박감 0~3, 배변 0~40), 수분은 0~60잔, 영양값은 0 이상의 숫자
- 형식이 맞는 기록은 한 값도 바꾸지 않음(멱등) — `tests/checks/load_state.cjs`로 확인
- 이 함수는 앱을 여는 순간 실행되므로, 뒤에서 정의되는 값(`today`, `md`, `EXTRA` 등)을 쓰지 않음
  (쓰면 초기화 전 참조 오류로 **정상 기록을 손상으로 오인**하게 됨)

## 백업·초기화·암호화(v1.10.0~v1.12.0)

- **자동 백업**: 기록이 바뀐 날마다 하나씩 최근 7일치를 IndexedDB(`uc-table-auto`의 `snaps`)에 둡니다. PC 크롬·엣지에서 폴더를 고르면(`showDirectoryPicker`) 기록이 바뀔 때 `uc-table-auto-날짜.json`을 쓰고 30일이 지난 파일을 지웁니다.
- **백업 암호화(선택, v1.11.0)**: 비밀번호에서 PBKDF2-SHA256 31만 회로 AES-GCM 256 열쇠를 만들어(`encDerive`) 백업 파일·복사·보내기·자동 백업 폴더 내용(`backupOut`)을 암호화합니다. 열쇠는 꺼낼 수 없는(`extractable:false`) CryptoKey로 IndexedDB(`kv`의 `bkKey`)에 두어 자동 백업도 묻지 않고 암호화합니다. 불러올 때 암호화된 백업이면 비밀번호를 묻습니다. 기기 안 보관본·CSV·PDF는 평문입니다.
- **전체 초기화(v1.11.0 H1)**: 기록 본체와 함께(확인 창 스위치를 켜 둔 기본값) 자동 보관본·불러오기 전 기록(`uc-table.v1.prev`)·손상 사본(`uc-table.v1.broken.*`)·폴더 연결·암호화 열쇠를 지우고(`wipeLocalCopies`), 안드로이드 앱에서는 브리지 `wipeOld()`로 옮겨 둔 예전 기록과 예전 `file://` 저장소를 비웁니다.
- **초기화 전 보관본(v1.12.0 C-04)**: 확인 창 스위치를 끄고 초기화하면 초기화 직전 기록을 `오늘~before-reset` 열쇠로 따로 보관합니다(`keepBeforeReset`). 초기화 뒤 자동 보관이 오늘 보관본을 빈 기록으로 덮어도 이것으로 되살립니다. 일부를 못 지우면 초기화 알림이 그렇게 말합니다(`wipeLocalCopies`가 결과를 돌려줌, C-13).
- **암호화 설정을 못 읽으면 멈춤(v1.12.0 C-07)**: `encLoad`가 IndexedDB를 읽지 못하면 '꺼짐'이 아니라 '준비 안 됨'(`ENC.err`)으로 두고, `encWrap`은 평문 대신 오류(`enc-unknown`)를 내 백업 파일·복사·보내기·자동 폴더 쓰기를 멈춥니다. 백업 화면에 '확인 못 함 · 다시 확인'.
- **누른 그 순간에 복사·공유(v1.12.0 C-10)**: 사파리는 클립보드·공유를 사용자가 누른 직후에만 허용합니다. 암호화 꺼짐이 확인되면 백업 글을 바로(동기) 만들고(`backupNow`), 켜져 있으면 복사는 `ClipboardItem`에 암호문 Promise를 넘기고 보내기는 진료용 PDF처럼 '준비됨 → 한 번 더 누르기'로 합니다.
- **백업 파일 입력칸(v1.12.0 C-20)**: `<input type=file id=restore>`는 다시 그리는 곳(`#main`) 밖 `body`에 하나만 둡니다. 파일 창이 열린 사이 화면을 다시 그려도 고른 파일이 버려지지 않습니다.
- **파일 이름(v1.11.0)**: `uc-table-backup-날짜.json`, `uc-table-symptoms|meals-날짜.csv`, `uc-table-report-날짜.pdf`, `uc-table-reminder.ics`(영문, 기기·메일에서 깨지지 않게).

## 홈 상태 띠(v1.11.0 디자인 A '잔잔한 능선', v1.12.0 후속 '바다'·'한밤')

- v1.12.0 후속 디자인: 제목 막대(`.appbar`)와 이 띠(`.ridge`)를 머리 띠 색(`--band`) 한 덩어리로 잇고, 점수 2점 기준은 띠 위 끝에 점선(`.thr`)을 더합니다. 바로 아래가 날짜 띠(`.hero-days`), 그 아래 오늘 끼니(`.list.meals`), 그 아래 오늘 할 일·영양 요약입니다(수정 요청서 v2 항목 1).
- `ridgeText()`가 오늘 상태 한 문장(어제·지난 기록과 비교, 활동기 기준이면 '증상이 활발합니다')과 점수·범위 한 줄을(v1.12.0부터 범위 문장은 식단 단계와 같은 `activity()` 기준: 관해 기준에 맞습니다·증상이 남아 있습니다·활동기 기준입니다. 그래프 띠 이름은 '점수 2점 이하'), `ridgeSVG()`가 최근 15일 배변·혈변 점수(0~6점) 능선을 그립니다.
- 세로 눈금은 6점 이상(5점 활동기 기준이 위쪽), 0점 선은 관해 범위 띠(2점 이하) 안쪽, 3일 넘게 빈 날은 선을 끊고, 기록 1일이면 점만 그립니다. 빠른 기록 날은 빈 동그라미. 날짜는 2주 전·1주 전·오늘 세 개.
- 그래프 폭은 화면 폭에 맞춰 viewBox를 다시 잡아(창 크기가 24px 넘게 바뀌면 다시 그림) 글자 크기가 화면 크기와 상관없이 같게 보입니다. 화면 읽기용 요약은 `aria-label`.

## 알림·줄바꿈·외식 판정 이유·진료 문서(수정 요청서 v2, v1.12.0)

- **알림 상자(`toast`)**: 위쪽 알림(`.toasts.top`)에는 아래쪽 알림용 `bottom:96px` 규칙이 걸리지 않게 `body.pushed .toasts:not(.top)`로 좁혔습니다(둘이 함께 걸리면 상자가 화면 높이로 늘어남). 글자는 알약 가운데에 오고, 왼쪽에 × 버튼과 같은 44px 빈칸(`.toast::before`)을 둬 좌우가 대칭입니다. 되돌리기 같은 동작 버튼이 있는 알림(`.has-act`)은 글자 칸이 좁아지지 않게 빈칸 없이 글자 칸 안에서 가운데로 둡니다. 버튼은 `.t-btns` 한 묶음입니다.
- **줄바꿈**: 줄 끝에서 갈라지면 안 되는 말('지금: 값', 띄어쓰기 없이 '·'로 이은 짧은 나열)은 `.nb`(`inline-block`, `max-width:100%`)로 묶습니다. `nowrap`이 아니라서 한 줄에 들어가면 통째로 다음 줄로 넘어가고, 그보다 길 때(글자 200%·320px)만 안에서 나뉘어 가로로 넘치지 않습니다. 묶는 일은 `groupRefs()`가 부르는 `bindDots(root)`가 글 노드에서 하고(`textContent`는 그대로, 보이지 않는 글자 없음), 묶음 길이는 '·' 14자, ':' 24자까지입니다. 문단 끝 한 단어는 `text-wrap: pretty`, 짧은 안내·제목은 `balance`로 줄입니다(모르는 브라우저는 무시). 진료 문서(`#report`·`#printDoc`)와 인용(`.qa-ev`)은 제외합니다.
- **외식 판정 이유 줄(항목 6)**: 결과 카드에 '걸린 말: 이유' 줄을 `mjLines()`가 만듭니다. 이유 문장은 앱에 이미 있는 것(`WHY_REDMEAT`·`WHY_FATTY`·`WHY_FODMAP`은 음식 판정 `foodStatus`와 같은 상수, `AVOID_TAG`·`GLOSS`·`ruleCheck`가 만든 문장·음식 목록의 설명)만 쓰고, 걸린 낱말은 `kwWords()`가 찾습니다. 결과의 `lines`가 화면 줄, `lines0`은 종류가 많은 메뉴(broad)가 가장 엄격한 후보에서 가져온 기본 줄(재확인 때 다시 씀)입니다. 판정 단계와 '주의보다 낮게 두지 않음' 규칙은 건드리지 않습니다.
- **진료 문서(시안 v7)**: 글자 PDF(`printReport()` → `#printDoc` → 브라우저 인쇄)와 그림 PDF(`exportPDF()` → `#report` → html2canvas → jsPDF)가 `reportBlocks()` 한 곳의 같은 블록을 씁니다. 그래프는 `drawStoolChart()`(막대 = 낮+밤 배변 횟수, 빨간 점 = 혈변이 있었던 날, 속이 빈 막대 = 빠른 기록, 그래프 틀도 캔버스 안에 그림)가 그리고, SCCAI 열·추이·평균은 문서에서 뺐습니다(`sccai()`·`activity()`는 그대로이고 앱 안·CSV에는 SCCAI가 남음). 인쇄 CSS는 표가 없는 블록을 쪽 사이에서 쪼개지 않게(`#printDoc .blk:not(:has(table)){break-inside:avoid}`) 해 제목만 쪽 끝에 남는 것을 막습니다. jsPDF 기본 글꼴은 한글을 못 그려서 바닥글의 '날짜 작성'은 캔버스 그림으로 붙이고 쪽 번호만 `pdf.text`로 씁니다(`tests/checks/pdf7.cjs`가 `pdf.text`에 한글이 없는지 봅니다).

## 단계 판정

증상 기록에서 `activity()`가 세 단계 중 하나를 고릅니다. 화면에 보이는 점수는 `pro2()`(배변 횟수 점수 0~3 + 혈변 점수 0~3, 평소 하루 배변 횟수 `profile.usualBM`을 기준으로 함)이고 `twGrade()`가 Truelove-Witts 중증도를 참고로 정합니다. 옛 합산 점수(`symSum()`, 5점 이상)는 보이지 않는 보조 규칙으로 남아 있습니다(decisions.md 30번).
사용자가 직접 단계를 고정할 수도 있습니다(`stageMode`).

| 단계 | 이름 | 기준 |
|---|---|---|
| 1 | 섬유를 줄인 식사(저잔사식) | 활동기. 섬유·질긴 질감·자극을 줄이고 부드럽게 익힌 음식 |
| 2 | 조금씩 늘리는 식사(이행식) | 증상이 가라앉는 중. 익힌 채소와 단백질을 조금씩 넓힘 |
| 3 | 골고루 먹는 식사(지중해식) | 관해기. 채소·과일·통곡물·생선 중심, 가공식품·붉은 고기 제한 |

화면은 쉬운 말을 먼저 쓰고 용어는 괄호로 붙입니다(`STAGES[n].plain`, `stg(n)`, v1.11.0). 용어 풀이는 `GLOSS`(35개).

## 음식 판정

`foodStatus(음식, 맥락)`은 다음을 차례로 확인해 가장 강한 판정과 그 이유만 돌려줍니다.

1. 절대 금지(`ban`) — 아질산염(발색제)을 넣은 가공육(`BAN_TAG`), 술(`BAN_TAG`)과 원재료에 주정·에탄올이 든 제품·외식 메뉴 글(`alcWords`: 요리에 넣는 맛술·미림은 막지 않고, 청주·과실주·와인·소주는 재료 칸에서만 요리용으로 봄. 술빵·와인삼겹살·와인 소스·맥주 반죽처럼 술 낱말 바로 뒤에 익히는 요리 낱말이 오는 이름도 막지 않음), 고른 알레르기와 직접 적은 알레르기(v1.11.0, 이름·포장 원재료)
2. 당알코올 — 원재료에 말티톨·자일리톨·솔비톨 등이 있으면 양과 관계없이 '피하기'(`polyWords`: 음식·외식 글·원재료 확인·영양성분표 모두. 근거 Monash·IOIBD, 알코올과 달리 절대 금지는 아님)
3. 개인 조건 — 유당, 의료진 지시, 싫어하는 음식, 개인 주의 음식, 면역을 누르는 약을 쓰는 동안 날음식(v1.11.0, CDC), 새우·게 가운데 하나에 알레르기가 있을 때 다른 갑각류(교차 반응, `crustCross`, v1.12.0 C-21: 음식·외식·포장 원재료 판정이 같은 규칙)
4. 항상 피하는 음식(`ms = 9`) — 초가공식품, 튀김, 신장질환자용·경관급식 전용 영양식 등
5. 단계 조건 — 음식의 시작 단계(`ms`)가 현재 단계보다 높으면 '다음 단계'
6. 속성 조건 — 섬유량(한 끼 2 g 기준), 채소 35 g 상한, 짠 음식·기름진 음식, 매운 양념,
   가스를 늘리는 재료(FODMAP), 질긴 질감, 1회 분량 나트륨, 특수의료용도식품·질환용 영양식
7. 자료 없음 — 저잔사식 단계에서 식이섬유 값이 없는 식물성 음식은 양 기준을 확인할 수 없어 '주의해서'

햄이 흔히 들어가는 일반 음식(김밥·오므라이스·볶음밥, `hamopt` 태그)은 판정은 그대로 두고 '햄·소시지는 빼고 드십시오…' 안내(`HAM_NOTE`)를 붙입니다.
'대신 이것'(`altFoods`)은 직접 고른 목록(`ALT`)과 같은 쓰임·주재료의 일반 음식만 점수로 고르고(과자·양념·음료·시판 제품 제외), 맞는 것이 없으면 숨깁니다(v1.11.0).

영양값이 없는 항목은 0으로 치지 않습니다. `hasNut(음식, 영양소)`로 확인하고, 합계(`totals`)는 자료가 있는 값만 더한 뒤
빠진 음식 이름을 따로 모아(`miss`) 화면에 "○○ 자료가 없는 △△는 합계에서 빠졌어요"로 알립니다.

외식 메뉴 판정(`ruleCheck`)은 먼저 개인 조건을 검사하고,
메뉴 이름이 목록의 음식과 정확히 일치하면 그 음식의 판정을 그대로 씁니다.
일치하지 않을 때만 재료 이름에서 키워드를 찾아 판단합니다(곤약면·당면처럼 '면'이 붙어도 밀이 아닌 것은 제외 목록으로 거름).

## 예시 식단(오프라인)

`samplePlan()`은 7일 식단을 만듭니다(v1.7.0부터 앱의 유일한 식단 방식).

1. 메뉴 <!--n:menus-->1,174<!--/n-->개(생성 + 직접 쓴 메뉴 + 내가 만든 메뉴) 중 모든 식품이 그날 판정을 통과한 것만 씀(저잔사식은 채소 반찬 한 끼 1가지)
2. 날짜마다 목록의 다른 위치에서 시작해, 한 주에 같은 메뉴·같은 점심·저녁 주재료를 먼저 건너뜀
3. 끼니 평가가 '좋음'인 식품이 든 메뉴를 먼저, '나쁨'인 식품은 뺌. 관해기에는 지중해식 메뉴를 먼저
4. 아침 단백질은 하루 목표의 20%(적어도 12 g) 이상, 나트륨은 끼니와 하루 누적으로 상한 안
5. 체중과 BMI로 정한 열량(저체중 35·정상 30·비만전단계 이상 25 kcal/kg, 대한비만학회)·단백질(ESPEN) 목표에 맞춰 밥·죽·면(0.8~1.5배)과 단백질 반찬(최대 1.5배) 양을 조절
6. 끼니마다 곁들임을 하나 붙이는데, 그 끼니까지 쌓인 칼슘이 하루 권장섭취량의 1/3·2/3·전부에 못 미치면 칼슘 100 mg 이상인 곁들임(우유·요거트 등)을 먼저 고름(관해기 저녁에는 지중해식 곁들임 먼저)
7. 관해기에는 양을 조절한 뒤 하루 식이섬유가 충분섭취량에 못 미치면 곁들임을 섬유가 더 많은 것으로 바꿈(나트륨 상한 안, 칼슘은 줄이지 않음)

교체한 메뉴는 메뉴 키로 저장하고(`setSwap`), 메뉴 고르기 화면에서 직접 고르거나 내가 만든 메뉴로 바꿀 수 있습니다.

## 내 정보 편집과 저장(v1.7.1)

기본 정보·알레르기·복용 약·식성·의료진 지시 화면은 열 때 `S.profile`·`S.orders`를 복사한 초안(`PE`)을 만들고, 화면의 입력과 버튼은 초안만 바꿉니다(`PP()`·`PO()`). '저장'(`peSave`)을 눌러야 초안을 기록에 넣고 기기에 저장합니다. 뒤로 가기·취소에서 초안이 처음과 다르면(`peDirty`) 저장할지 묻고, 버리면(`peDiscard`) 입력칸 값을 다시 읽지 않고 닫습니다(`peLeave`). 편집 화면을 벗어나면 그리기 전에 초안을 버립니다.

## 영양 화면·목표(v1.8.0)

- `targets()`는 BMI(`bmiInfo`)로 체중 1 kg당 열량을 고르고, 사용자가 정한 목표(`S.goals`)가 있으면 그 값으로 바꾼 뒤 바꾼 항목을 `custom`에 적습니다.
- 먹은 양 합계(`eatenTotals`)는 '먹음'을 누른 끼니(비율 반영)와 직접 추가한 음식을 더합니다. 막대(`dbarHTML`)는 계획한 양과 먹은 양을 한 줄에 그리고, `shortOK(날짜)`(지난 날이거나 오늘 19시 이후)일 때만 모자람을 경고색으로 칠합니다.

- FODMAP 1회량(`FSERV`, 빌드 때 `fodmap_serv.py`에서 넣음)과 요리 값 종류(`DISHX`)는 음식 정보·먹은 음식 추가·끼니 화면에서 씁니다.

## 궁금한 점(v1.7.0)

`QA`(빌드 때 `qa.py`에서 넣음)는 질문·핵심어·답·근거(자료 이름, 위치, 원문 문장, 참고문헌 번호)·관련 음식을 담습니다.

- 검색(`qaMatch`): 검색어가 핵심어와 같으면 3, 핵심어에 들어 있거나 두 글자 이상 핵심어가 검색어에 들어 있으면 2, 질문에 있으면 1, 답에만 있으면 0.5. 한 글자 핵심어(물·술·회·굴)는 같을 때만 맞춰 '물김치'가 수분 질문에 걸리지 않게 함
- 음식 검색은 점수 1 이상인 질문을 3개까지 결과 위에 보여 주고, 음식 정보는 그 음식을 `foods`에 둔 질문을 보여 줌
- 질문 화면(`scrQA`)은 종류 칩과 검색, 펼친 답 안의 관련 음식 칩(지금 판정), 근거 원문 펼치기로 구성. 결과 목록은 음식 검색처럼 같은 내용이면 다시 그리지 않음(`setListHTML`)
- 인용문 대조는 앱이 아니라 단위 점검이 함([근거 목록](evidence.md#궁금한-점의-근거-원문-대조v170))

### 서비스 워커(설치형 앱) 갱신

- 캐시 이름 = `uc-table-` + `public/index.html` 내용의 SHA-256 앞 10자리. 앱이 바뀌면 `sw.js`가 바뀌고, 브라우저가 새 워커를 설치합니다.
- 설치할 때 `cache:"reload"`로 받아 HTTP 캐시에 남은 옛 파일이 새 캐시에 섞이지 않게 합니다.
- 새 워커가 켜지면 옛 캐시(`uc-table-*`)를 지우고, 이후 여는 화면부터 새 버전이 나옵니다.
- 요청은 캐시 우선(오프라인에서도 즉시 열림), 캐시에 없으면 네트워크에서 받아 저장합니다.

### 알림

서버가 없어 서버 푸시는 쓰지 않습니다. '기록 알림'(증상 기록이 3일 넘게 없으면)은 환경에 따라 기기 안에서 만듭니다(`remindKind`).

- 안드로이드 앱: 브리지 `setLogReminder(켬, 마지막 기록 날짜)` → 기기 알람(저녁 8시 무렵, 하루 한 번까지, 재부팅 뒤 다시 걸기)
- 설치한 웹앱(크롬): 서비스 워커의 주기적 백그라운드 동기화 + 알림 권한, 마지막 기록 날짜는 캐시 `uc-remind-status`에만
- 그 밖(브라우저 탭·오프라인 파일): 앱을 닫으면 알릴 방법이 없어, 식사·증상 기록 시간을 매일 반복하는 캘린더 파일(`uc-table-reminder.ics`)을 안내
- 어느 경우든 앱을 열면 홈에 안내를 띄우고, 지원하는 곳에서는 앱 아이콘 배지를 씁니다.
