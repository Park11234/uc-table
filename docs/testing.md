# 점검 체계

```bash
npm ci && npx playwright install --with-deps chromium   # package-lock.json 그대로 설치
npm run lint          # ESLint — 오류·경고 0 유지(--max-warnings 0)
npm run test:py       # tests/python — 데이터 생성 코드 단위 점검 <!--n:pytests-->86<!--/n-->개(표준 라이브러리만)
npm test              # tests/run-all.sh — Playwright <!--n:pw-->55<!--/n-->개 파일 전부 실행
node tests/visual/visual.cjs            # 화면 비교(v1.8.0). 의도한 디자인 변경 뒤에는 --update로 기준 화면을 다시 만듦
npm run test:mutation # tests/mutation-check.sh — 일부러 망가뜨린 앱 <!--n:mutants-->58<!--/n-->개를 점검이 잡는지(CI는 매주 한 번, mutation.yml)
BROWSER=webkit node tests/webkit/webkit.cjs   # 아이폰 사파리 엔진(WebKit) 흐름(v1.11.0, CI의 webkit 작업. 이 개발 환경은 BROWSER=chromium으로 점검 코드만 확인)
node tools/doc_numbers.cjs     # 문서의 숫자 표시(<!--n:…-->)가 지금 빌드와 같은지(--fix, v1.11.0)
python3 tools/stale_check.py   # 확인한 지 1년 넘은 근거(참고문헌·FODMAP 1회량·궁금한 점). 기한 90일 전부터는 경고(--soon, v1.11.0)
python3 tools/link_check.py    # 링크 형식 점검(--online: 실제로 열어 응답 확인, 매달 GitHub Actions)
python3 tools/tone_check.py    # 앱 문구에 해요체(~요)가 남았는지(원문 인용·자료 제목은 제외)
```

각 점검은 `src/app/index.html`을 그대로 감싼 페이지를 **실행할 때마다 새로 만들어** 검사합니다.
(예전에 만들어 둔 임시 파일을 재사용하면 옛 빌드를 검사하게 되는 문제가 실제로 있었습니다.)
실패한 파일의 로그는 `.test-out/`에 남고, CI에서는 아티팩트로 올라갑니다.

## CI에서 매 커밋 확인하는 것

1. **ESLint** — 정의되지 않은 변수, 도달할 수 없는 코드, 중복 키 등 23개 규칙. 경고도 0이어야 통과.
2. **빌드 재현** — 생성 스크립트를 다시 돌린 결과가 커밋된 앱·PWA와 바이트 단위로 같아야 통과.
3. **파이썬 단위 점검 <!--n:pytests-->86<!--/n-->개** — 아래 표(v1.10.0 데이터 규칙은 `test_v110.py`, v1.11.0은 `test_v111.py`).
4. **근거 확인일·링크 형식·문구 말투** — `tools/stale_check.py`(1년 넘은 근거가 있으면 실패), `tools/link_check.py`(https가 아니거나 주소 모양이 이상하면 실패), `tools/tone_check.py`(앱 문구에 해요체가 남으면 실패).
5. **Playwright <!--n:pw-->55<!--/n-->개 + 화면 비교** — 아래 표. WebKit 흐름 점검은 따로 `webkit` 작업에서(아이폰 사파리와 같은 엔진).
6. **점검의 점검** — 앱을 일부러 <!--n:mutants-->58<!--/n-->가지 방식으로 망가뜨려(`tests/mutation-check.sh`) 해당 점검이 실제로 실패하는지 <!--n:pairs-->60<!--/n-->쌍을 확인.
   점검이 아무것도 확인하지 않고 늘 통과하는 상태로 변하면 여기서 걸립니다.
   오래 걸려 v1.10.0부터는 매 커밋이 아니라 매주 한 번과 손으로 실행할 때만 돕니다(`.github/workflows/mutation.yml`, 개발자 12).
   **실패 알림(v1.11.0 L10)**: 매주 작업이 실패하면 GitHub가 저장소 주인에게 Actions 실패 메일을 보냅니다(GitHub 설정 → Notifications → Actions에서 '실패만' 켜 두기). **출시 전에는 손으로 한 번** `npm run test:mutation`을 돌리거나 Actions의 mutation 작업을 'Run workflow'로 실행하고, 결과를 출시 기록에 남깁니다.
7. **문서 숫자** — `node tools/doc_numbers.cjs`가 README·docs·공개 페이지에 표시해 둔 숫자를 빌드와 대조합니다(v1.11.0 M7).

의존성은 `package-lock.json`에 고정하고 CI는 `npm ci`로 그대로 설치합니다(설치할 때마다 버전이 바뀌지 않게).

## 모든 점검이 값을 확인합니다(v1.5.0)

v1.4.0까지는 45개 중 34개가 화면 흐름을 끝까지 실행하고 값을 **출력만** 했습니다(누를 요소가 없거나 페이지 오류가 날 때만 실패).
v1.5.0에서 이 34개에 기대값 확인을 넣었습니다. 출력한 줄을 모아 두었다가 끝에서 비교하고, 하나라도 다르면 종료 코드 1로 끝납니다.

넣고 나서 실제로 걸린 것:

- **다시 그리면 입력이 사라짐** — 나이·싫어하는 음식·기타 알레르기·기타 복용약·오늘 몸무게·기타 증상 칸 6곳은 저장 전에 다른 버튼을 누르면 적던 글자가 지워졌습니다(`checks/retain.cjs`).
  예전 점검은 이 결과를 출력만 해서 통과했습니다. 지금은 11개 화면의 입력칸이 모두 확정 전 글자를 기억합니다.
- **식단 점검이 옛 규칙을 확인** — 레시피 판정에 음식 사전 식품을 빼고 확인해 멀쩡한 식단을 틀렸다고 출력하고 있었고,
  반대로 '계란국' 메뉴가 달걀 레시피(재료: 삶은 달걀)를 가리키는 실제 불일치는 묻혀 있었습니다(`regression/t13.cjs`). 둘 다 고쳤습니다.
- **큰 글자·어두운 모드에서 가로 넘침** — 끼니 카드의 버튼 두 개가 한 줄에 들어가지 않았습니다(`regression/t8.cjs`).

모든 점검에는 공통 안전장치가 들어 있어, 어느 페이지에서든 잡히지 않은 오류(`pageerror`)가 나면 그 점검은 실패합니다.

## 사람처럼 써 보는 점검(v1.11.0)

자동 점검이 모두 통과해도 실제로 써 보면 걸리는 것이 있어, 디자인을 바꾼 뒤 agent-browser(헤드리스 크롬)로 PWA 빌드를 처음 쓰는 사람처럼 끝까지 썼습니다.
동의 → 시작 설정 3단계 → 홈 → 증상 기록 5쪽 → 끼니 먹음·안 먹음·바꾸기 → 음식 검색(한글·영어·오타·햄·김밥) → 음식 정보 → 외식 판정 → 편의점 제품 → 내 정보·백업·암호화 → 앱 정보(어두운 화면·아주 크게) → 검사 수치 → 2주 기록이 있는 홈 → 320px·PC 폭.
찾은 24건(높음 1·중간 11·낮음 12)은 화면 사진과 함께 기록해 고치고, `checks/review2.cjs`로 다시 생기지 않게 했습니다. 이 점검으로만 잡힌 대표 사례는 실제 앱에만 남은 body 기본 여백(점검 페이지는 여백을 지워 가려졌음)입니다.

## 사용성 평가(다음 단계)

환자를 모신 사용성 평가는 아직 하지 않았습니다(v1.11.0 U-13). 출시 전에 직접 진행할 방법입니다.

1. 대상: 궤양성 대장염 환자 5~8명(관해기·활동기 섞어서, 휴대폰 크롬·아이폰 사파리 사용자 섞어서). 개인 정보는 받지 않고 앱의 기록은 평가 기기에서 지웁니다.
2. 과제(각 5분 안): 첫 실행 설정 마치기, 오늘 증상 기록하기(빠른 기록 포함), '김밥'과 '바나나'를 찾아 먹어도 되는지 말하기, 외식 메뉴 하나 판정하기, 백업 파일 만들기, 진료용 PDF 만들기.
3. 측정: 과제 성공 여부·걸린 시간·막힌 곳(말하며 하기), 끝나고 SUS 10문항(68점 이상이 보통 이상), '쉬운 말'(섬유를 줄인 식사 등)을 바로 이해했는지.
4. 기록: 막힌 곳마다 화면·문구를 적어 다음 버전 검토 보고서에 넣습니다.

실기기 확인(안드로이드 APK 덮어 설치·뒤로 가기·알림·카메라, 아이폰 홈 화면 추가)도 직접 하실 일로 남깁니다(이 개발 환경에는 기기·에뮬레이터가 없음).
