# UC TABLE v1.11.0 구현 계획

> 실행: superpowers:executing-plans(이 세션에서 직접 구현) + 마지막에 새 검토자 1명이 브랜치 전체 검토. 단계는 체크박스로 추적.

**목표:** v1.10.0 검토 보고서(높음 5·중간 11·낮음 12)를 모두 고치고, 사용자가 고른 디자인(A안 '잔잔한 능선' + '맑은 파랑')으로 화면 전체를 바꾼 v1.11.0을 만든다.

**구조:** 단일 원본 `src/app/app.src.html`(화면·판정·기록) + 파이썬 데이터 생성(`src/data/*.py` → `generated/`) + 빌드(`build_app.py` → `src/app/index.html` → `tools/build_offline.py` → `public/`, `dist/`) + 안드로이드 껍데기(`android/`). 판정·기록 수정은 원본과 데이터에서, 디자인은 CSS 토큰·공통 부품·홈 머리를 바꾼다.

**기술:** 바닐라 JS·CSS, Python 3.11(pandas), Playwright 1.56(Chromium), Java 8 소스(aapt·dalvik-exchange·apksigner로 Gradle 없이 빌드).

**디자인 근거:** 사용자 확정(2026-10-17) — A안 잔잔한 능선, 색은 맑은 파랑. 시안: 세션 산출물 `UC_TABLE_디자인_3안.html`, `UC_TABLE_A안_색_3가지.html`. 능선 그래프 아래 날짜는 일주일 간격.

## 전역 제약

- 판정 어휘와 뜻은 그대로: 좋음·주의·다음 단계·피하기·절대 금지(색 + ●▲■✕ 모양).
- 8번(M4): 3일 연속 알림과 하루 알림의 행동 문장은 같은 한 문장 "주치의(IBD 진료팀)에 알리십시오."로 고정.
- 색 토큰(밝은 화면): 바탕 #F5F7FB, 카드 #FFFFFF, 머리 띠 #E3ECFF, 강조 #1F5EDB, 강조 옅음 #E8EFFF, 글자 #0E1A2E, 보조 글자 #4B5A70. 판정 색: 좋음 #1F6E3D/#E1F2E6, 주의 #8A5200/#FFEFD3, 피하기 #A8261B/#FCE6E3, 절대 금지 흰 글자/#7A1B13.
- 글꼴: Pretendard(OFL-1.1) 가변 글꼴을 앱이 쓰는 글자 + KS X 1001 한글로 줄여 내장(웹은 별도 파일, 오프라인·APK는 data URL). 라이선스 고지 포함.
- 그림자·그라데이션 없음(바탕색 차이로 구역), 버튼은 둥근 알약 모양, 카드 모서리 20~26px.
- 오프라인 우선: 외부 주소(CDN·웹 글꼴) 없음. 안드로이드는 인터넷 권한 없음.
- 개인정보: 처리방침·확인 창 문구가 실제 동작과 같아야 함.
- 화면 문구에 줄표(—) 대신 쉼표·마침표.

## 검토 초점(시험이 따로 없으면 놓치기 쉬운 것)

1. 빠른 기록만 있는 날 — 목록·PDF·CSV·그래프 어디서도 '밤 0회·복통 0'으로 읽히지 않을 것.
2. 전체 초기화 직후 새로고침 — 보관본·옛 손상 사본·불러오기 전 기록이 하나도 되살아나지 않을 것.
3. 기록이 2주보다 적거나 하루뿐일 때 홈 능선 그래프 — 깨지지 않고 '기록이 쌓이면 보입니다'.
4. 어두운 화면·320px·PC 640px에서 새 디자인 — 글자 잘림·대비 부족 없음.
5. 면역억제제를 골랐다 지웠을 때 — 날음식 판정이 피하기 ↔ 원래대로 바로 돌아올 것.

## 작업

### 1. 점검 파일과 빠른 기록 표시(H2)
- 파일: `tests/checks/v1110.cjs`(새로), `src/app/app.src.html`(기록 목록·PDF 표·CSV·추이 그래프)
- 시험: 빠른 기록 날 목록 줄에 '빠른 기록'·'하루 6회', PDF 표에 '빠른'·밤/복통 칸 '–', CSV '낮 배변' 대신 '하루 합계', 그래프 점 모양이 다름.

### 2. 전체 초기화 범위(H1)
- `resetDo`: IndexedDB `snaps` 비우기, `KEY.prev`·`KEY.broken.*` 지우기, 자동 백업 폴더 연결(핸들) 지우기, 안드로이드 `UCTableAndroid.wipeOld()` 부르기. 확인 창 문구에 지워지는 범위를 적음.
- 시험: 보관본 2개 + 손상 사본 + PREV를 만든 뒤 초기화 → 모두 0, 새로고침 뒤 기록 0.

### 3. 안드로이드(H1·H3·L7)
- `MainActivity.java`: START 첫 로딩 뒤 `web.clearHistory()`, 옮기기 실패면 표시를 남기지 않고 다음 실행에서 재시도, `wipeOld()`(migrated-v1.json·예전 file:// 저장소 삭제), `isAndroidApp()`.
- 앱: 설정의 '덮어 설치' 안내는 안드로이드 앱에서만.
- 빌드: 같은 릴리스 키로 서명, versionCode 11100, versionName 1.11.0.

### 4. 날음식과 면역억제제(H5)
- 근거 확인(공공 기관 면역저하자 식품 안전 안내) 뒤 REFS 새 번호로 넣고, 복용 약에 스테로이드·면역조절제·생물학적 제제·JAK 억제제가 있으면 `raw` 태그 음식은 '피하기' + 이유 문장.
- 시험: 약 없음 → 주의, immuno → 피하기, 약 지우면 → 주의.

### 5. 알림 한 문장(M4, 8번)
- 두 알림의 행동 문장을 상수 하나로. 시험: 3일 연속·하루 모두 같은 문장, '고려하십시오' 없음.

### 6. 대신 이것·시판 표시(M1·M2)
- 데이터에 음식마다 `prod`(시판) 표시를 넣고 `isProd`는 그것만 본다. 대안은 직접 고른 목록(ALT)을 늘리고, 자동 대안은 같은 분류의 일반 음식만(과자·젤리·양념·음료·시판 제외), 맞는 게 없으면 칸을 숨긴다.
- 시험: 초밥·초콜릿·호두·꿀의 대안에 과자·젤리·양념 없음, 과자 52종·영양식 26종이 시판으로 셈.

### 7. 햄이 들어갈 수 있는 음식·훈제오리(M3)
- 일반 음식 중 설명에 햄·소시지가 나오는 것(김밥 등)은 판정은 두고 "햄·소시지가 들어가면 절대 금지입니다. 빼고 드십시오." 안내를 붙인다. 훈제오리는 앱의 시판 훈제오리 원재료에서 아질산나트륨 비율로 결정(햄과 같은 방식).
- 시험: 김밥 정보에 안내, 훈제오리 판정이 규칙과 같음(파이썬 단위 점검).

### 8. 검색 자모(M5)
- 자모 일치는 마지막 글자가 덜 완성됐거나 완성 글자로 맞는 결과가 없을 때만.
- 시험: '햄' → 파전·바지락칼국수 없음, 'ㅎㅐ' 입력 중에는 여전히 찾음.

### 9. 1회 분량(M6)
- CJ 일품요리·즉석 죽을 반찬·누룽지에서 빼고 포장 1인분 규칙. 점검: '요리인데 1회 분량이 총량의 15% 미만' 0건.

### 10. 확인 날짜·안 먹음(M8·M9)
- 추정 날짜는 "2026-09-24 이전(첫 공개판)"처럼, 설정 이름은 '마지막으로 음식을 넣은 날'. 끼니 줄 버튼 '안 먹음·바꾸기', 안 먹은 끼니는 줄에 상태 표시.

### 11. 백업 암호화·동기화 폴더 안내(M10)
- 폴더 고를 때 OneDrive·구글 드라이브·iCloud 동기화 폴더 안내. 선택형 비밀번호 암호화(PBKDF2-SHA256 31만 회 → AES-GCM 256): 백업 파일·자동 폴더 백업, 불러오기에서 비밀번호 물음.
- 시험: 암호화 백업 → 평문에 메모 없음, 맞는 비밀번호로 복원, 틀리면 거절.

### 12. WebKit 점검(M11)
- CI에 Playwright WebKit 작업(홈·기록·찾아보기·백업 흐름). 이 환경은 WebKit이 없어 CI에서만.
