# AI와 함께 만든 방법

이 앱은 AI 코딩 도구(Claude)와 협업해 만들었습니다.
이 문서는 **AI에게 무엇을 맡겼고, AI가 만든 결과를 어떻게 검증했는지**를 정리한 것입니다.
핵심은 "AI가 빨리 만들고, 사람이 정한 기준과 자동 점검이 그것을 걸러 낸다"는 구조입니다.
AI는 만드는 과정에만 썼고, v1.7.0부터 앱 자체는 AI를 호출하지 않습니다(아래 '앱에서 AI를 뺀 결정').

## 역할 나누기

| 사람(개발자)이 한 일 | AI가 한 일 |
|---|---|
| 문제 정의: 누구의, 어떤 순간의 불편을 풀지 | 요구사항을 화면·데이터 구조·규칙으로 설계 |
| 제약 설정: 근거 없는 규칙 금지, 기록은 기기 밖으로 보내지 않기, 기능보다 신뢰성 | 코드 구현, 음식 데이터 생성 파이프라인, 테스트 작성 |
| 근거 수준 요구: 진료지침·병원 식이 안내·논문으로 판정을 검토하라 | 지침·논문 조사, 판정 규칙과 근거 번호 연결 |
| 사용 중 발견한 문제 보고, 수정 방향 결정 | 원인 분석, 수정, 회귀 점검 |
| 무엇을 빼고 무엇을 남길지 결정(검사 수치 입력 제외 등) | 결정의 영향 범위 확인, 문서화 |

## 검증 장치

AI가 만든 결과는 그대로 믿지 않고, 아래 장치를 통과한 것만 남겼습니다.

1. **근거 추적** — 모든 판정 문구에 지침·논문 번호를 붙이게 했습니다. 번호가 없는 규칙은 넣지 않았고,
   원문을 읽지 못한 자료 2건은 인용에서 뺐습니다([evidence.md](evidence.md)).
2. **원자료 대조** — 음식 영양값은 AI가 적지 않고, 식약처 DB에서 이름으로 행을 찾아 붙이는 스크립트로 만들었습니다.
   병원 저잔사식 허용·제한 목록과 앱의 단계 판정을 전수 대조하는 점검도 따로 돌립니다(`gil_audit`).
3. **자동 점검 <!--n:pw-->57<!--/n-->개 + 파이썬 <!--n:pytests-->88<!--/n-->개** — 화면 흐름, 한글 입력, 좁은 화면, 다크 모드, HTML 주입, 오프라인 동작,
   설치형 앱 갱신, 접근성(WCAG 2.2 AA, 터치 영역 44 px), 저장 데이터 손상 퍼징까지 Playwright로 확인하고,
   데이터 생성 코드(영양식 표시값 환산, 메뉴, 빌드 재현)는 파이썬 단위 점검으로 확인합니다. CI에서 매 커밋마다 실행되며,
   모든 화면의 버튼을 눌러 보고 검색칸에 이상한 검색어를 넣는 퍼징(누름 약 2,400회)과 주요 화면 10개의 픽셀 비교도 돌리고,
   앱을 <!--n:mutants-->70<!--/n-->가지로 일부러 망가뜨려 점검이 실제로 실패하는지도 확인합니다(매주, 출시 전 한 번 더). 문서에 적은 숫자는 `tools/doc_numbers.cjs`가 빌드와 대조합니다(v1.11.0).
6. **인용문 원문 대조(v1.7.0)** — 궁금한 점의 답에 붙인 근거 문장 <!--n:qaev-->169<!--/n-->건은 AI가 요약한 문장이 아니라 원문의 글자 그대로여야 하고,
   원문 파일과 한 글자라도 다르면 단위 점검이 실패합니다. 해외 지침은 원문 페이지에서 발췌문이 본문에 그대로 있는지 브라우저로 다시 확인했습니다.
4. **정적 분석** — 앱 스크립트를 ESLint 23개 규칙으로 검사하고 경고 0을 유지합니다.
5. **재현 가능한 빌드** — 앱 빌드를 다시 돌리면 배포본과 바이트 단위로 같은 파일이 나와야 CI가 통과합니다.
   손으로 고친 흔적이 끼어들 수 없습니다. 영양 데이터 생성은 pandas·numpy 버전을 맞춰야 같은 결과가 나옵니다.
7. **사람처럼 써 보는 점검(v1.11.0)** — 디자인을 바꾼 뒤 agent-browser로 PWA 빌드를 처음 쓰는 사람처럼 첫 실행부터 기록·검색·외식 판정·백업·설정까지 끝까지 써 보고, 찾은 것을 화면 사진과 함께 기록한 뒤 고치고 점검(`review2.cjs`)으로 남겼습니다.

## 검증이 잡아낸 문제들

AI가 처음 만든 결과에서, 위 장치들이 실제로 걸러 낸 사례입니다.

| 발견 경로 | 문제 | 조치 |
|---|---|---|
| 원자료 대조 | 식약처 DB의 일부 행이 비정상적인 섬유량을 가짐(멸치볶음 10.1 g, 잡곡밥 6.1 g 등) | 같은 음식의 다른 분석 계열과 비교해 10개 행을 코드로 고정 |
| 원자료 대조 | 고형 음식 28종의 기준량이 `100ml`로 표시됨(원자료 표기 문제) | 마시는 음식이 아니면 `100g`으로 표기 |
| 근거 대조 | 한 음식에 "피하세요"와 "소량만 드세요"가 함께 표시됨 | 가장 강한 판정의 이유만 보이도록 판정 함수 수정 |
| 근거 대조 | FODMAP 등급 일부가 공개 자료와 다름(파프리카) | 공개 자료에서 확인한 등급만 남기고 나머지는 '자료 없음' |
| 데이터 점검 | 알레르기 키워드 오검출(땅콩버터→우유, 햄버거→돼지고기, 감잣국→잣) | 예외 규칙 추가, 점검 스크립트로 전수 재확인 |
| 데이터 점검 | 알레르기 표시 누락(김밥의 생선, 굴소스의 밀, 고추장의 대두 등) | 태그 보강 |
| 점검 코드 검토 | 일부 테스트가 오래전 만든 임시 파일(옛 버전 앱)을 검사하고 있었음 | 모든 테스트가 실행 때마다 현재 소스로 페이지를 새로 만들도록 변경 |
| 스크린샷 작업 | 저장된 성별 값이 예상 밖이면 첫 화면 전체가 오류 화면으로 바뀜 | 방어 코드 추가, 같은 종류의 문제를 찾는 손상 퍼징 점검 신설 |
| 설계 검토 | 서비스 워커 캐시 이름이 고정돼, 앱을 고쳐도 설치된 기기는 옛 화면에 머묾 | 앱 내용 해시로 캐시 이름을 만들고, 새 파일을 HTTP 캐시를 건너뛰어 받도록 변경 |
| 손상 퍼징 | 기록 1,040가지 변형 중 거대한 숫자 하나로 앱이 멈추고(그래프 눈금 계산), 두 화면이 오류로 바뀌고, `NaN`·`[object Object]`가 여러 곳에 노출됨 | 불러오기 단계에서 날짜·글자·숫자 범위를 확인 → 오류·멈춤·노출 0 |
| 접근성 검사 | 어두운 화면의 '전체 초기화' 버튼 글자 대비 2.7:1 | 버튼 전용 색으로 5.6:1 |
| 화면 검토 | 식단이 바뀌어 끼니가 없어지면 '끼니 상세'가 빈 화면으로 남음 | 안내 문구와 돌아가기 버튼 |
| 점검 코드 검토 | 기존 점검 40개가 결과 값을 출력만 하고 확인하지 않아, 틀려도 통과함 | 주요 6개에 단언 추가(새 점검 4개와 함께 단언형 10개), 전체에 페이지 오류 안전장치, 일부러 망가뜨린 앱으로 점검이 실제로 실패하는지 확인 |

| 화면 검토 | '김'을 검색하면 고기만두·돼지고기 목살이 김보다 먼저 보임(한글 조합 중 검색을 위한 자모 일치의 부작용) | 결과 목록은 그대로 두고, 같은 판정 안에서 이름 일치가 먼저 오도록 정렬 |
| 자가 점검(v1.5.0) | 29가지 부족한 점 목록을 AI가 스스로 만들고, 사용자가 고칠 항목을 골라 수정(나트륨·지방 규칙, 값이 없는 영양소를 0으로 더하던 문제, 메뉴 교체를 목록 번호로 저장하던 문제 등) | 항목마다 점검과 돌연변이를 함께 추가 |

| 원문 재대조(v1.7.0) | 궁금한 점을 만들며 참고문헌 요약을 저장한 원문과 다시 맞추자, 세브란스병원 요약이 조건부 안내(염증이 심할 때·빈혈일 때)를 조건 없이 적었고, 대한장연구학회 브로셔 요약의 생백신 시기(최소 4주 전)가 사백신 시기(2주 전)로 적혀 있었음 | 원문대로 고치고, 이후 답의 근거는 요약이 아니라 원문 문장을 그대로 싣고 기계로 대조 |

## 고치면서 피한 위험

수정도 새 오류를 만들 수 있어, 바꾸기 전에 영향 범위를 먼저 확인했습니다.
예를 들어 저장 데이터 정리 함수에 날짜 도우미(`today`)를 쓰려다, 이 함수가 **앱을 여는 순간** 실행되고
`today`는 그보다 뒤에 정의된다는 것을 확인했습니다. 그대로 썼다면 모든 사용자의 정상 기록이
"손상된 기록"으로 표시됐을 것입니다. 함수 안에 독립적인 검사 도구를 따로 두고,
저장→새로고침→비교 점검(`load_state`)을 새로 만들어 같은 종류의 실수를 막았습니다.

## AI를 쓰며 지킨 원칙

- **"됐다"는 보고를 믿지 않고 증거를 요구한다.** 테스트 결과, 대조표, 스크린샷으로 확인합니다.
- **한 번에 하나씩 고치고, 고칠 때마다 전체 점검을 다시 돌린다.**
- **모르는 것은 모른다고 남긴다.** 확인하지 못한 자료, 실제 기기에서 확인하지 못한 부분은 문서에 한계로 적었습니다.
- **판단은 결정적인 코드에, 생성은 AI에.** 같은 입력에 항상 같은 판정이 나오는 부분만 사용자에게 "먹어도 된다"고 말합니다.
